# CI Integration Guide

How to integrate living-docs into your CI/CD pipeline.

## Strategy: Two-Phase Documentation Updates

The new model has two phases because docs live in two places:

**Phase 1 -- Per-MS Update** (runs in each service repo's CI):
1. Merge to main/develop triggers CI
2. CI runs living-docs analysis
3. CI updates `{service}/docs/index.md` within the same repo
4. CI opens a PR in the service repo with the doc changes

**Phase 2 -- Sync into docs-microservices** (runs in docs-microservices CI or manually):
1. Triggered after Phase 1 PRs merge, or on schedule
2. Runs `sync-to-central.sh` to map per-MS docs into the Obsidian Vault structure in docs-microservices
3. Opens a PR in docs-microservices with synced changes
4. Optionally checks flow impact

This separation keeps each repo's CI simple and avoids cross-repo write dependencies.

## Phase 1: Per-MS Doc Update

Place this in each microservice repo at `.github/workflows/update-docs.yml`:

```yaml
name: Update Living Docs
on:
  push:
    branches: [main, develop]
    paths-ignore:
      - 'docs/**'     # Don't trigger on doc-only changes (avoid loops)
      - '*.md'

jobs:
  update-docs:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write

    steps:
      - name: Checkout service repo
        uses: actions/checkout@v4
        with:
          fetch-depth: 0  # Full history needed for commit range analysis

      - name: Get last documented SHA
        id: last-sha
        run: |
          DOC_FILE="docs/index.md"

          if [[ -f "$DOC_FILE" ]]; then
            SHA=$(grep -m1 'last_documented_sha:' "$DOC_FILE" | sed 's/.*: *"\?\([^"]*\)"\?/\1/' | tr -d ' ')
            echo "sha=$SHA" >> $GITHUB_OUTPUT
            echo "exists=true" >> $GITHUB_OUTPUT
          else
            echo "sha=" >> $GITHUB_OUTPUT
            echo "exists=false" >> $GITHUB_OUTPUT
          fi

      - name: Detect changes
        id: changes
        run: |
          if [[ "${{ steps.last-sha.outputs.exists }}" == "true" && -n "${{ steps.last-sha.outputs.sha }}" ]]; then
            FROM_SHA="${{ steps.last-sha.outputs.sha }}"
          else
            # No existing docs: use last 50 commits as starting point
            FROM_SHA=$(git rev-list --max-count=50 HEAD | tail -1)
          fi

          # Run change detection (copy script from living-docs or install as dependency)
          bash .living-docs/scripts/detect_changes.sh \
            --repo . \
            --from "$FROM_SHA" \
            --to HEAD > /tmp/changes-report.txt

          echo "from_sha=$FROM_SHA" >> $GITHUB_OUTPUT

          if grep -qE "CRITICAL|HIGH|MEDIUM" /tmp/changes-report.txt; then
            echo "has_changes=true" >> $GITHUB_OUTPUT
          else
            echo "has_changes=false" >> $GITHUB_OUTPUT
          fi

          cat /tmp/changes-report.txt

      - name: Run living-docs analysis
        if: steps.changes.outputs.has_changes == 'true'
        run: |
          bash .living-docs/scripts/analyze_commits.sh \
            --repo . \
            --from "${{ steps.changes.outputs.from_sha }}" \
            --to HEAD \
            --output /tmp/living-docs-analysis.json

          # NOTE: The actual doc generation step depends on your setup.
          # Options:
          # A) Claude API call with analysis + current docs as context
          # B) Deterministic script for simple updates (frontmatter, changelog)
          # C) Flag for manual update
          #
          # At minimum, update the frontmatter:
          if [[ -f "docs/index.md" ]]; then
            sed -i "s/last_documented_sha:.*/last_documented_sha: \"$(git rev-parse HEAD)\"/" docs/index.md
            sed -i "s/last_updated:.*/last_updated: \"$(date -u +%Y-%m-%d)\"/" docs/index.md
          fi

      - name: Create PR with doc updates
        if: steps.changes.outputs.has_changes == 'true'
        uses: peter-evans/create-pull-request@v5
        with:
          branch: docs/update-${{ github.sha }}
          title: "docs: update from ${{ github.sha }}"
          body: |
            ## Auto-generated by living-docs

            **Commits covered**: ${{ steps.changes.outputs.from_sha }}...${{ github.sha }}

            Please review the documentation changes before merging.
          labels: documentation, auto-generated
```

### How to make living-docs scripts available in each repo

Three options, choose one:

**Option A -- Git submodule** (recommended for small teams):
```bash
# In each service repo:
git submodule add https://github.com/your-org/living-docs.git .living-docs
```
Scripts are at `.living-docs/scripts/`. Update with `git submodule update --remote`.

**Option B -- Copy scripts into each repo**:
Add `scripts/living-docs/` to each repo. Simpler but harder to keep in sync.

**Option C -- npm/package dependency**:
Publish living-docs scripts as a package. Install in CI. Best for larger teams.

## Phase 2: Sync into docs-microservices

Place this in the docs-microservices repo at `.github/workflows/sync-docs.yml`:

```yaml
name: Sync Service Docs to Vault
on:
  # Trigger via webhook from service repos, or on schedule
  workflow_dispatch:
    inputs:
      service:
        description: 'Service to sync (leave empty for all)'
        required: false
  schedule:
    - cron: '0 */6 * * *'  # Every 6 hours

jobs:
  sync:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write

    steps:
      - name: Checkout docs-microservices
        uses: actions/checkout@v4

      - name: Checkout all service repos
        run: |
          mkdir -p /tmp/repos

          # List your services here (or fetch from a config file)
          SERVICES="integrator sap magento"

          for service in $SERVICES; do
            git clone --depth 1 \
              https://x-access-token:${{ secrets.DOCS_REPO_TOKEN }}@github.com/your-org/$service.git \
              /tmp/repos/$service || echo "Warning: could not clone $service"
          done

      - name: Run sync
        run: |
          SERVICE_FLAG=""
          if [[ -n "${{ github.event.inputs.service }}" ]]; then
            SERVICE_FLAG="--service ${{ github.event.inputs.service }}"
          fi

          bash scripts/sync-to-central.sh \
            --repos-dir /tmp/repos \
            --docs-repo . \
            $SERVICE_FLAG

      - name: Check for changes
        id: check
        run: |
          if [[ -n "$(git status --porcelain)" ]]; then
            echo "has_changes=true" >> $GITHUB_OUTPUT
          else
            echo "has_changes=false" >> $GITHUB_OUTPUT
          fi

      - name: Create PR
        if: steps.check.outputs.has_changes == 'true'
        uses: peter-evans/create-pull-request@v5
        with:
          branch: sync/update-${{ github.run_id }}
          title: "docs(sync): sync service docs to Vault structure"
          body: |
            ## Auto-synced from service repos

            This PR syncs per-service documentation from each service's
            `docs/` directory into the Obsidian Vault structure in docs-microservices.

            Mapping rules (see `references/central-mapping.md`):
            - `docs/components/` -> `reference/{repo}/`
            - `docs/changelogs/` -> `reports/changelogs/`
            - `docs/adrs/` -> `engineering/adrs/`
            - `docs/runbooks/` + `docs/guides/` -> `engineering/guides/`
            - `docs/technical/` -> `reference/{repo}/`
            - `docs/bugs/` -> `reports/`
            - `docs/plans/` -> `strategy/`
            - `docs/tasks/` -> `engineering/microservices/{repo}/`

            **Remember**: The source of truth is `{service}/docs/`.
            If you need to edit service docs, edit the source in the service repo.
          labels: documentation, auto-synced
```

## Freshness Audit (scheduled)

Add to docs-microservices at `.github/workflows/freshness-audit.yml`:

```yaml
name: Doc Freshness Audit
on:
  schedule:
    - cron: '0 9 * * 1'  # Every Monday at 9 AM
  workflow_dispatch:

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout docs
        uses: actions/checkout@v4

      - name: Checkout all service repos
        run: |
          mkdir -p /tmp/repos
          SERVICES="integrator sap magento"
          for service in $SERVICES; do
            git clone --depth 1 \
              https://x-access-token:${{ secrets.DOCS_REPO_TOKEN }}@github.com/your-org/$service.git \
              /tmp/repos/$service || true
          done

      - name: Run freshness check
        run: |
          bash scripts/check-freshness.sh \
            --repos-dir /tmp/repos \
            --docs-repo . > freshness-report.md
          cat freshness-report.md

      - name: Create issue if stale
        if: always()
        uses: peter-evans/create-issue-from-file@v4
        with:
          title: "Weekly Doc Freshness Report"
          content-filepath: freshness-report.md
          labels: documentation, audit
```

## Secrets Required

| Secret | Purpose | Where |
|--------|---------|-------|
| `DOCS_REPO_TOKEN` | GitHub PAT with repo scope | Each service repo + docs-microservices |

## Important Notes

1. **Phase 1 creates PRs in the service repo** -- doc changes version with the code.
2. **Phase 2 syncs copies to the Vault structure** -- it maps each doc type to its correct location in docs-microservices (not a flat mirror).
3. **Neither phase auto-merges**. Human review is always required.
4. **The doc generation step in Phase 1 is a placeholder.** Options: Claude API call, deterministic script, or manual flag. Start with just updating frontmatter and grow from there.
5. **Start simple**: Begin by just running `detect_changes.sh` and `check-freshness.sh` in CI. Add automated generation later.
6. **paths-ignore on `docs/**`** in Phase 1 prevents infinite loops (doc change -> trigger -> doc change -> ...).
